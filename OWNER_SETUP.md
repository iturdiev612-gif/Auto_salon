# Инструкция владельцу The Family Auto

Эта инструкция передаётся владельцу отдельно. Она не включена в публичные страницы сайта. Реальные пароли, коды и ключи в этот файл не записывайте.

## Запуск на компьютере

Установите Node.js 24. В папке проекта выполните `npm install`, скопируйте `.env.example` в `.env`, заполните настройки и запустите `npm run dev`. Локальные данные сохраняются в `data/store.json`. Не удаляйте этот файл, если нужны существующие пользователи, заказы и отзывы.

## Настройки Vercel

В проекте Vercel добавьте переменные в Settings → Environment Variables, затем выполните новый deployment:

- `JWT_SECRET`: случайная строка длиной от 32 символов.
- `ADMIN_EMAIL`: личная почта единственного владельца панели.
- `ADMIN_BOOTSTRAP_SECRET`: отдельная случайная строка длиной от 32 символов для первой настройки.
- `TFA_STORE_URL` и `TFA_STORE_TOKEN`: HTTPS URL и токен REST API базы Upstash Redis.

Для каждого секрета генерируйте новое значение, например командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Не используйте один секрет для разных назначений. Не добавляйте секреты в переменные с префиксом `VITE_`: такие переменные попадают в браузер.

В Vercel укажите папку с `package.json` как Root Directory, команду сборки `npm run build`, Output Directory `dist`. Загружать только папку `dist` на статический хостинг недостаточно: для аккаунтов, заказов и отзывов нужен `api/router.js` и Redis. Без Redis production API намеренно не сохраняет данные во временной памяти.

## Первый доступ владельца

1. Откройте на своём домене `/owner/setup`. Публичной ссылки на эту страницу нет.
2. Введите почту из `ADMIN_EMAIL`, закрытый код из `ADMIN_BOOTSTRAP_SECRET`, имя и собственный пароль длиной от 12 символов.
3. После создания аккаунта откройте обычную страницу входа и войдите этой почтой и паролем. Панель откроется только владельцу.
4. После успешной настройки удалите `ADMIN_BOOTSTRAP_SECRET` из окружения и выполните redeploy. Повторная настройка существующего владельца заблокирована.

Обычная регистрация всегда создаёт покупателя. Поля и подсказки про администратора из неё удалены. Знание адреса страницы панели или изменение данных в браузере не даёт прав: сервер сверяет роль пользователя и почту из `ADMIN_EMAIL`.

Если аккаунт владельца уже существует, используйте вход или восстановление пароля. При передаче другому владельцу измените `ADMIN_EMAIL`, задайте новый `ADMIN_BOOTSTRAP_SECRET`, выполните redeploy и настройте новую почту на `/owner/setup`. Права предыдущего владельца больше не пройдут серверную проверку. После передачи снова удалите код настройки.

## Восстановление забытого пароля

Для автоматической отправки письма настройте один из вариантов:

- SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. Обычно порт 587 и `SMTP_SECURE=false`, либо 465 и `true`; точные значения выдаёт почтовый провайдер.
- Resend: `RESEND_API_KEY` и `MAIL_FROM` с адресом на подтверждённом домене. API: [Send Email](https://resend.com/docs/api-reference/emails/send-email).

После настройки выполните redeploy и проверьте доставку настоящего письма. Без настроенного отправителя письмо не может быть отправлено. Пользователь увидит понятное сообщение и ссылку на связь с автосалоном; пароль по одному email не раскрывается и не сбрасывается.

Покупатель нажимает «Забыли пароль?», указывает почту, получает шестизначный код и задаёт новый пароль. Код действует 15 минут, число попыток ограничено, после смены пароля старые сессии перестают работать. Код и пароль никогда не выводятся на сайте.

Ручное восстановление через поддержку допустимо только после проверки принадлежности аккаунта. Не выдавайте доступ человеку только потому, что он назвал чужой email.

## Заказы и уведомления

Покупатель выбирает машину, входит или регистрируется, заполняет контакты и адрес и нажимает «Подтвердить заказ». Заказ сохраняется, получает уникальный номер и доступен в истории покупателя и панели владельца. Цена и скидка рассчитываются сервером. Для проверки статуса нужно войти в аккаунт, которым оформлен заказ.

По умолчанию выбрана оплата после согласования с менеджером. Stripe и Post.kg в этом проекте работают в тестовом режиме; реальное списание денег не подключено. Для реального онлайн-платежа нужна отдельная интеграция платёжного провайдера и webhook.

Заявки доступны в панели даже без уведомлений. Для Telegram настройте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Письма о доставке и уведомления о заказах используют существующие SMTP-настройки; Resend добавлен для восстановления пароля.

## Каталог и фотографии

В стартовом каталоге 20 карточек: по пять моделей Toyota, Mercedes-Benz, Honda и Lamborghini. У каждой модели свой локальный файл фотографии. Исправление старых стандартных карточек не удаляет заказы, пользователей и отзывы и не подменяет фотографии, введённые владельцем.

Это стартовый каталог, а не подтверждённый склад автосалона. Перед публикацией владелец должен проверить цены, наличие, год, комплектацию, цвет, пробег и состояние по реальным автомобилям и заменить иллюстрации фотографиями своего склада. Единицы мощности hp и PS/CV оставлены по данным соответствующих производителей, без смешивания стандартов.

Источники фотографий и лицензии доступны по ссылке в подвале сайта и в `public/cars/credits.json`. Иллюстрации показывают модель и поколение; конкретный год и оснащение на фотографии могут отличаться. Фото Wikimedia Commons необходимо сохранять с указанием авторства и лицензии, если вы оставляете их на сайте.

## Проверки перед передачей сайта

Выполните `npm test` и `npm run build`. После публикации проверьте на настоящем домене регистрацию покупателя, вход владельца, заказ, новый отзыв после обновления страницы и доставку письма восстановления. Локальные тесты не подтверждают настройку внешних аккаунтов Vercel, Redis и почты.
