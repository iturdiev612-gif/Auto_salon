# The Family Auto

Современный React/Vite-сайт автосалона: 20 моделей Toyota, Mercedes-Benz, Honda и Lamborghini; кыргызский, русский и английский языки; адаптивная вёрстка.

## Запуск

```powershell
npm install
npm run dev
```

Откройте адрес Vite из терминала (обычно `http://localhost:5173`). REST API и Socket.io запускаются плагином Vite. При первом запросе каталога создаётся `data/store.json`.

Для первой настройки администратора задайте `ADMIN_EMAIL` и уникальный `ADMIN_BOOTSTRAP_SECRET` в `.env`, затем откройте `/owner/setup` и настройте владельца по отдельной инструкции. Не используйте общий адрес или публичный код. JWT подписывает backend; пароль хранится как scrypt-хэш. Админские API проверяют роль.

## Публикация на Vercel через GitHub

1. Убедитесь, что в GitHub загружены папки `api/`, `src/` и файл `vercel.json`.
2. В Vercel задайте Root Directory как папку проекта с `package.json`, `api/` и `vercel.json`, Build command — `npm run build`, Output directory — `dist`, затем нажмите **Redeploy** (или отправьте новый commit в подключённую ветку). Node.js 24.x закреплён в `package.json`.
3. В Vercel → **Settings → Environment Variables** обязательно задайте `JWT_SECRET` (случайный секрет не короче 32 символов), `ADMIN_EMAIL`, `ADMIN_BOOTSTRAP_SECRET` и подключите Upstash Redis, добавив `TFA_STORE_URL` и `TFA_STORE_TOKEN` из его REST API credentials. Без этих переменных production API не запустится, чтобы не терять данные и не использовать тестовый секрет.
4. После успешного deployment откройте `https://ваш-домен.vercel.app/api/cars`. Ответ должен быть JSON-массивом автомобилей. Затем обновите сайт на телефоне.

Vercel запускает API из папки `api/` как serverless functions; Socket.IO на продакшене выключен, а статус заказа обновляется периодическим запросом. Каталог кэшируется на CDN на 30 секунд; отзывы запрашиваются без кэша, чтобы новый отзыв был виден сразу. Записи в Redis защищены проверкой версии, поэтому параллельные изменения не перезаписывают друг друга молча. Демо OAuth отключён в production; Google/GitHub OAuth доступен после настройки клиентских ключей и callback URL. Демо-оплата не списывает деньги.

### Уведомления о заказах в Telegram

API отправляет владельцу сообщение при новой покупке, бронировании и заявке из формы контактов. Для включения уведомлений:

1. Создайте бота через `@BotFather` командой `/newbot` и скопируйте токен. Не публикуйте токен в GitHub и не вставляйте его в React-код.
2. Откройте своего нового бота в Telegram и нажмите **Start**. Узнайте свой Telegram chat ID через бота `@userinfobot`.
3. В Vercel откройте **Settings → Environment Variables** и добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Сохраните секреты и выполните новый Deploy.
4. Проверьте отправку тестовой заявкой с сайта. Если настройки добавлены только для локального запуска, поместите их в свой `.env` и перезапустите `npm run dev`.

Заказы требуют, чтобы приложение было развёрнуто с API из `api/`. Без этих двух переменных заявки остаются доступны в админ-панели, но бот не получит уведомления.

## Функции

- Корзина, избранное, заказ, бронь, регистрация и вход с JWT.
- Отдельные страницы регистрации и входа (`/register`, `/login`); бургер-меню доступно на больших и маленьких экранах.
- Бронирование сохраняется в API и открывает готовую заявку в WhatsApp на номер `+996 999 42 5453`.
- Отдельная страница `/booking` с именем, телефоном, автомобилем, личной встречей, тест-драйвом или онлайн-консультацией и комментарием; выбранная модель подставляется автоматически.
- Кнопка «Купить сейчас» открывает оформление выбранного автомобиля; оставить отзыв можно в разделе отзывов.
- Оформление заказа вынесено на отдельную страницу `/order`; после подтверждения открывается личное отслеживание `/tracking?reference=...`.
- Страница отслеживания показывает пять этапов доставки и схематичный маршрут по Бишкеку. Статус меняет менеджер в админ-панели; при каждом изменении этапа клиенту отправляется email (нужны SMTP-переменные). Маршрут пока схематичный и не показывает GPS-положение; API 2ГИС ещё не подключён.
- Чтобы посмотреть ранее созданный заказ, откройте «Отследить заказ» в меню и введите номер заказа. Нужен тот же аккаунт, которым оформлялась покупка.
- Каталог с поиском, фильтрами и пагинацией.
- Админ CRUD: добавить, изменить и удалить машину; статистика графиком.
- Skeleton загрузки, React Error Boundary и demo chatbot.
- Socket.io отправляет обновления каталога и отзывов в реальном времени.
- Telegram и SMTP email уведомления при наличии данных в `.env`.
- Cloudinary загрузка при настройке unsigned upload preset.
- Google/GitHub OAuth-интерфейс; production demo-вход отключён. Провайдеры требуют отдельной серверной интеграции и проверки callback, сейчас API отвечает 503.
- Stripe/Post.kg выбор оплаты в интерфейсе и demo endpoint. Реальные платежи не списываются.

## Подключение внешних сервисов

Скопируйте `.env.example` в `.env`, заполните параметры сервиса и перезапустите Vite. Никогда не публикуйте `.env` и не добавляйте секретные ключи с префиксом `VITE_`: переменные `VITE_*` доступны браузеру. Только Cloudinary cloud name и unsigned preset являются публичными значениями.

Для OAuth задайте client ID/secret, добавьте callback адреса из `.env.example` в настройках Google/GitHub и включите `VITE_GOOGLE_OAUTH_ENABLED`/`VITE_GITHUB_OAUTH_ENABLED`. Для Telegram и email укажите bot/chat или SMTP-реквизиты. Для Cloudinary укажите cloud name и unsigned preset.

Stripe и Post.kg здесь подключены только как демонстрационные способы оплаты. Для реального приёма денег нужно создать checkout на защищённом backend, настроить merchant аккаунт и подтверждение платежа/webhook; не храните платёжные секреты в React.

## API

- `GET /api/cars`; `POST/PUT/DELETE /api/cars` — CRUD, администратор.
- `GET/POST /api/reviews` — отзывы.
- `POST /api/auth`, `POST /api/auth/reset/request`, `POST /api/auth/reset/confirm`, `POST /api/auth/logout`, `GET /api/me`, `GET /api/me/orders`, `GET /api/oauth/{google|github}` и callback-маршруты — вход, восстановление пароля, выход и профиль.
- `GET /api/admin/stats` — статистика, администратор.
- `POST /api/orders`, `POST /api/payments`, `POST /api/bookings` — заказ, демо-оплата и бронь; в заказе сохраняется адрес доставки.
- `GET /api/me/orders` — история заказов текущего пользователя; `POST /api/auth/logout` — завершение сессии; `GET /api/orders/:reference` — статус своего заказа; `GET /api/admin/orders` и `PATCH /api/admin/orders/:reference` — управление этапом доставки администратором.

## Финансовый учёт и подготовка к запуску

- В админ-панели есть график оборота, закупочной стоимости проданных машин, операционных расходов и расчётной прибыли за последние 6 месяцев. Расходы вносятся вручную и сохраняются в общем хранилище.
- При добавлении автомобиля указывайте закупочную цену. Новые заказы сохраняют эту стоимость на момент покупки, чтобы последующее изменение карточки не меняло прошлые расчёты. Старые заказы без закупочной цены отмечаются как неполные и могут завышать прибыль.
- В каталоге есть подсказки поиска, фильтры по марке, кузову, максимальной цене, году, топливу и коробке, пагинация, сортировка по цене, рейтингу, году и названию, сохранение поиска, сравнение до трёх автомобилей. Неуказанные характеристики нужно заполнить в админке.
- В Vercel обязательно подключите Upstash Redis (`TFA_STORE_URL`, `TFA_STORE_TOKEN`), задайте `JWT_SECRET` минимум из 32 символов, `ADMIN_EMAIL` и отдельный `ADMIN_BOOTSTRAP_SECRET` для отдельной однократной настройки владельца. Без Redis API в production вернёт понятную ошибку вместо временного хранения в памяти.
- Демо-вход OAuth отключён в production; для Google/GitHub нужны ключи и callback URL из текущего домена. Stripe и Post.kg остаются демонстрационными: для приёма денег нужен merchant-аккаунт, серверная интеграция и проверка webhook. Убедитесь, что выбранный способ оплаты соответствует реально настроенному процессу до запуска рекламы или приёма денег.

Финансовый график показывает данные заказов и расходов, внесённых в систему. Это не бухгалтерская отчётность и не прогноз гарантированной прибыли.

### Новые функции и письма о доставке

- Менеджер создаёт процентные или фиксированные купоны в админке. Скидка повторно проверяется сервером при оформлении заказа; можно задать дату окончания и лимит применений.
- При изменении этапа доставки клиенту отправляется письмо на email из заказа. Для отправки задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` и, при необходимости, `SMTP_FROM`. Админка покажет, если почта не настроена.
- Каталог позволяет сохранять до пяти поисков в браузере. В карточке автомобиля есть ориентировочный ежемесячный платёж; это пример, не кредитное предложение.
- При снижении цены в карточке показывается прежняя цена и дата изменения. Каталог больше не меняет страницу сам во время просмотра.

Вдохновляющие элементы: сравнение машин и пометка о снижении цены — [Autotrader](https://www.autotrader.com/help/shopping-for-cars); сохранённые поиски — [Cars.com](https://www.cars.com/mobile-app/); сравнение и ценовая прозрачность — [CarGurus](https://www.cargurus.com/about/how-cargurus-works); калькулятор платежа — [Carvana](https://www.carvana.com/partner-financing); запись на тест-драйв уже есть в форме бронирования, похожий сценарий описывает [CarMax](https://www.carmax.com/faq/finding-a-car/if-i-find-a-car-i-like-online-can-i-see-it-in-person-before-i-make-a-decision).

## Карта проекта и хранение данных

### Где искать код

- `src/App.jsx` — состояние магазина, каталог и запуск маршрутов; страницы заказа, бронирования и отслеживания находятся в `src/pages/`.
- `src/components/` — переиспользуемые части: форма телефона, купоны, финансовая панель, чат, граница ошибок и калькулятор кредита.
- `src/pages/AuthPage.jsx` — регистрация, вход и сброс пароля; `OrderPage.jsx`, `BookingPage.jsx`, `TrackingPage.jsx` — отдельные страницы магазина.
- `src/i18n/copy.js` — тексты интерфейса на русском, кыргызском и английском.
- `src/data.js` — демонстрационный список автомобилей для первого запуска.
- `src/data/siteContent.js` — марки и слайды главного баннера.
- `src/lib/api.js`, `src/lib/storage.js`, `src/lib/format.js` — HTTP-запросы, чтение настроек браузера и формат цены.
- `api/router.js` — production API Vercel и проверка прав пользователя.
- `vite.config.js` — локальный API для разработки; локальные записи лежат в `data/store.json`.
- `src/enhancements.css` — адаптивность и дополнительные стили компонентов.
- `.env.example` — список переменных окружения; реальные значения храните только в `.env` или Vercel.

### Где хранятся данные

| Данные | Локальная разработка | Vercel |
| --- | --- | --- |
| Автомобили, пользователи, заказы, брони, отзывы, купоны, расходы и коды сброса пароля | `data/store.json` | Upstash Redis, ключ `the-family-auto-store-v1` |
| Корзина, избранное, сохранённые поиски, язык и тема | `localStorage` браузера (`tfa-cart`, `tfa-favorites`, `tfa-searches`, `tfa-lang`, `tfa-dark`) | `localStorage` браузера посетителя |
| Токен входа | `localStorage` браузера и HttpOnly cookie сессии | Bearer-токен и HttpOnly cookie сессии |
| Пароли | Только солёный scrypt-хэш в хранилище пользователей | Только солёный scrypt-хэш в Upstash Redis |
| Секреты API, почты, OAuth и Redis | `.env`, не добавлять в Git | Vercel → Settings → Environment Variables |

`localStorage` привязан к одному браузеру и устройству. Корзина, избранное и сохранённые поиски пока не синхронизируются между устройствами. Адрес доставки сохраняется в заказе; доступ к истории и статусу заказа проверяется по аккаунту покупателя.

### Поток запроса

```text
React page/component → src/lib/api.js → /api/*
                                      ├─ local: Vite middleware → data/store.json
                                      └─ Vercel: api/router.js → Upstash Redis
```

Для сброса пароля можно использовать Resend (`RESEND_API_KEY`, `MAIL_FROM`) или SMTP. Для писем о доставке нужен SMTP: используются те же `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` и `SMTP_FROM`. Код сброса хранится в виде хэша, действует 15 минут и инвалидирует прежние сессии после успешной смены пароля.
### Подключения перед публикацией

- В Vercel задайте `JWT_SECRET` (случайное значение длиной от 32 символов), `ADMIN_EMAIL`, `ADMIN_BOOTSTRAP_SECRET`, `TFA_STORE_URL` и `TFA_STORE_TOKEN`.
- Для писем о доставке и сброса пароля настройте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`.
- Чтобы включить Google: задайте `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_OAUTH_CALLBACK_URL=https://ВАШ-ДОМЕН/api/oauth/google/callback` и `VITE_GOOGLE_OAUTH_ENABLED=true`. Для GitHub используйте `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_OAUTH_CALLBACK_URL=https://ВАШ-ДОМЕН/api/oauth/github/callback` и `VITE_GITHUB_OAUTH_ENABLED=true`. Тот же callback URL добавьте в настройках OAuth-приложения у провайдера.
- Загрузка изображений использует Cloudinary и требует `VITE_CLOUDINARY_CLOUD_NAME` и `VITE_CLOUDINARY_UPLOAD_PRESET`.
- Stripe и Post.kg пока остаются demo-платежами. Для приёма денег нужно отдельно подключить платёжные аккаунты и webhook.

После настройки переменных нужно выполнить новый deployment в Vercel, чтобы production-сборка получила нужные `VITE_*` значения.

### Подключение писем с кодом восстановления

Скопируйте .env.example в .env и выберите один способ. Реальные ключи не добавляйте в Git и не указывайте в переменных VITE_.

SMTP:

```dotenv
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=your-mailbox@example.com
SMTP_PASS=your-provider-app-password
SMTP_FROM="The Family Auto <your-mailbox@example.com>"
```

Для порта 465 используйте SMTP_SECURE=true. Для Gmail и других провайдеров, требующих пароль приложения, используйте именно его. Если SMTP_FROM пуст, используется SMTP_USER.

Resend: укажите RESEND_API_KEY и MAIL_FROM с подтверждённым доменом отправителя. Если настроены оба способа, используется Resend. После изменения .env перезапустите npm run dev; на Vercel добавьте переменные проекта и выполните новое развёртывание.

Проверка вручную: зарегистрируйте собственный тестовый аккаунт, выйдите, нажмите «Забыли пароль?», введите его email, получите код, укажите новый пароль дважды и войдите. Код действует 15 минут, повторная отправка доступна через 60 секунд. Пять неудачных попыток исчерпывают лимит; при следующей попытке код блокируется. Код одноразовый, старые сессии после смены пароля недействительны. При отсутствии провайдера сайт честно сообщает, что почта недоступна. Рабочие почтовые реквизиты пока не заданы; реальную доставку в ваш ящик необходимо проверить после подключения. Автотест SMTP использует локальный тестовый почтовый сервер и никому не отправляет письма.

### Карта и 2ГИС

На карте пять примерных точек Бишкека по референсу. Это демонстрационные точки, не действующие автосалоны. Координаты и подписи: src/data/marketplace.js. Нажатие на адрес центрирует карту и открывает подпись; ссылка открывает выбранную точку в 2ГИС.

Для тайлов 2ГИС укажите VITE_2GIS_API_KEY (ключ сервиса Raster Tiles API, ограниченный доменом сайта). Документация: https://docs.2gis.com/en/maps/others/rastertiles/overview . Это публичный браузерный ключ. Если ключа нет или 2ГИС недоступен, используется рабочая карта OpenStreetMap с правильным указанием источника. Без ключа 2ГИС не выдаётся за источник тайлов.

Бесплатная альтернатива: создайте свою карту с этими точками в конструкторе 2ГИС, скопируйте только HTTPS-адрес src из iframe в VITE_2GIS_WIDGET_URL. Нужен аккаунт 2ГИС: https://docs.2gis.com/en/maps/others/map-constructor/overview . Полный HTML-код в эту переменную не вставляйте. Виджет имеет приоритет над картой из API; его метки редактируются в конструкторе 2ГИС.

### Социальные сети

Добавлены Threads, TikTok, Facebook, Instagram, Telegram и два YouTube-значка (KG / RU), как на референсе. Собственных аккаунтов пока нет, поэтому ссылки не выдуманы. Заполните VITE_SOCIAL_* в .env; после перезапуска или пересборки значки откроют ваши HTTPS-профили. До этого при нажатии выводится сообщение, что ссылка появится позже.

### Проверка и запуск

Node.js 24.x. Установка: npm ci. Запуск: npm run dev. Сборка: npm run build. Автотесты: npm test. Изменения внесены в исходную локальную папку проекта; публикация сайта отдельно не выполнялась.
